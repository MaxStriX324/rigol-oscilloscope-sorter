# Rigol Oscilloscope Sorter — автоматический архив осциллограмм

Сортировщик измерений **RIGOL DHO814 (DHO800)** и **DHO924S (DHO900)**. Подходит для архивирования экранов, аналоговых осциллограмм и настроек, сохранённых с помощью **Quick → Save Group** на SMB/Samba-ресурс. Пользователь сообщает об использовании DHO924S совместно с **16-канальным логическим пробником PLA2216**.

Проект основан на существующем рабочем `rigol_sort.py`; дополнен ожиданием **60 секунд после последнего изменения каждого файла группы**, непрерывным опросом папки каждые **5 секунд**, тестами и инструкциями.

> **Важно про логический анализатор:** скриншоты с цифровыми каналами D0–D15 и файлы настроек архивируются как обычные PNG/STP. Текущий парсер **не обещает извлечение всех 16 цифровых каналов в Excel из бинарного файла**. Оригиналы данных сохраняются, даже когда формируется XLSX для поддерживаемых CSV/BIN.

## Что делает

- Собирает одно измерение из файлов с одинаковым именем: `RigolDS1.png`, `RigolDS1.csv` (или `.bin`), `RigolDS1.stp`.
- Присваивает измерению общий сквозной номер `N000001`, время и дату, не перезаписывает уже существующие архивные файлы.
- Перемещает PNG и исходные данные в каталог `YYYY_MM_DD/`, а **STP — в `Seting/YYYY_MM_DD/`** (`Seting` — существующее имя каталога, сохранено для совместимости).
- Переводит поддерживаемые CSV/BIN в Excel (`XLSX`). Для больших файлов формирует части либо превью с разреженными отсчётами и Min/Max; оригинал не теряется.
- Пишет индекс `_logs/sort_index.csv`, журнал `_logs/sort_log.txt`, счётчик `_logs/rigol_counter.txt`; неудачные группы перемещает в `_failed/` с причиной.
- Поддерживает сетевые пути Windows UNC через `pushd` в командных файлах.

Пример структуры после обработки:

```text
RigolShare/
├── rigol_sort.py
├── run_rigol_sort.cmd
├── run_rigol_watch.cmd
├── 2026_10_20/
│   ├── D2026_10_20_N000001_T15_20_30.png
│   ├── D2026_10_20_N000001_T15_20_30.bin
│   └── D2026_10_20_N000001_T15_20_30.xlsx
├── Seting/2026_10_20/
│   └── D2026_10_20_N000001_T15_20_30.stp
└── _logs/
    ├── sort_index.csv
    ├── sort_log.txt
    └── rigol_counter.txt
```

## Быстрый старт: Windows + SMB (основная конфигурация)

Программа работает **на компьютере Windows**. Осциллографы записывают измерения в **расшаренную Windows-папку** от специально созданного локального пользователя. Сортировщик получает доступ к этому каталогу локально, без сетевого пароля и без установки Python на сам Rigol.

### 1. Подготовка папок на Windows 10/11

Рекомендуется отделить программу от приходящих файлов:

```text
C:\RigolSorter\               # здесь распаковать проект и запускать .cmd
C:\RigolData\DHO814\         # входящая папка первого прибора
C:\RigolData\DHO924S\       # входящая папка второго прибора, включая PLA2216
```

Папки приборов должны быть **разными**: иначе одинаковые названия `RigolDS1.png` от двух осциллографов могут попасть в одну группу.

### 2. Расшарить Windows-папку с отдельным пользователем

1. В Windows задайте профиль сети **Частная**. В дополнительных параметрах общего доступа включите **Сетевое обнаружение** и **Общий доступ к файлам и принтерам** для частных сетей. Общий доступ с парольной защитой оставьте **включённым**.
2. Создайте отдельного локального пользователя, например **`rigol_capture`**, с сильным паролем. *Параметры → Учётные записи → Другие пользователи → Добавить учётную запись → Добавить пользователя без учётной записи Microsoft.* (Названия разделов зависят от Windows.) Пользователю не нужны права администратора.
3. Для `C:\RigolData\DHO814` откройте **Свойства → Доступ → Расширенная настройка → Открыть общий доступ**, присвойте имя SMB-ресурса **`Rigol814`**. В **Разрешения** добавьте `rigol_capture` и дайте изменение/чтение; группу `Everyone` с лишними правами удалите.
4. Вкладка **Безопасность** (NTFS) того же каталога: добавьте `rigol_capture` с правами **Изменение**, необходимые права оставьте для своего пользователя и системы. *Важно: необходимы одновременно разрешения SMB и NTFS.*
5. Аналогично откройте `C:\RigolData\DHO924S` под именем **`Rigol924`**.
6. Узнайте IPv4 компьютера командой `ipconfig` и желательно закрепите адрес через DHCP на роутере. Для теста с другого ПК откройте `\\192.168.1.100\Rigol814` (замените адрес) и войдите под `ИМЯ_ПК\rigol_capture` и его паролем.
7. Разрешите **File and Printer Sharing** в брандмауэре Windows только для доверенной частной сети; **не открывайте TCP/445 в интернет и не включайте SMB1**, если SMB2/SMB3 работает.

### 3. Настроить SMB на каждом Rigol

Через меню **Storage → SMB Setting** (названия в разных версиях прошивки могут незначительно различаться):

| Параметр | DHO814 | DHO924S |
|---|---|---|
| Server Path | `\\192.168.1.100\Rigol814` | `\\192.168.1.100\Rigol924` |
| User Name | `ИМЯ_ПК\rigol_capture` либо `rigol_capture` | То же |
| Password | Пароль пользователя Windows | То же |
| Connect | Подключить и проверить состояние | Подключить и проверить состояние |
| Boot Auto_Connect | Включить по необходимости | Включить по необходимости |

Укажите подключённый сетевой диск в **Storage → File Path** как место сохранения Quick. Если не удаётся авторизоваться, проверьте точные учётные данные, оба набора разрешений и совместимость SMB; не отключайте парольную защиту ради упрощения.

### 4. Установка Python и запуск сортировщика

1. Скачайте **Code → Download ZIP**, распакуйте содержимое репозитория в `C:\RigolSorter`.
2. **Один раз** запустите **`install.cmd`**. Он найдёт установленный Python 3 или попробует поставить его для текущего пользователя через `winget`/подписанный официальный установщик Python; создаст `.venv` и установит в неё `openpyxl` из `requirements.txt` (нужен интернет).
3. Для постоянной работы откройте `run_rigol_watch.cmd`, измените одну строку:

   ```bat
   set "RIGOL_ROOT=C:\RigolData\DHO814"
   ```

   Либо не редактируйте командный файл и запустите его с папкой как аргументом:

   ```bat
   run_rigol_watch.cmd "C:\RigolData\DHO814"
   ```

4. Запустите `run_rigol_watch.cmd`. Он остаётся открытым, проверяет изменения каждые 5 секунд и перемещает **всю имеющуюся группу** в архив только спустя **60 секунд с последнего изменения** каждого файла. Приблизительно 60–66 секунд при отсутствии дополнительных задержек файловой системы. Остановка — `Ctrl+C`.
5. Для второго прибора используйте отдельный запуск с `C:\RigolData\DHO924S` (рекомендуется собственная копия программы или отдельный ярлык/скрипт; у одного экземпляра сортировщика только одна входная папка).
6. `run_rigol_sort.cmd` делает **один проход** по указанной папке и завершает работу — полезно для ручного запуска. Он также использует задержку 60 секунд. Файлы не должны быть моложе 60 секунд.

При повторном запуске `install.cmd` рабочая `.venv` повторно используется. Пароли приборов **не** записываются в настройки сортировщика. `start.cmd` для этой утилиты не требуется: главный запускаемый файл — **`run_rigol_watch.cmd`**.

### 5. Автозагрузка Windows

Создайте **Планировщик заданий → Создать задачу**: триггер **При входе пользователя** (или при включении компьютера при наличии доступа к папке); программа `cmd.exe`; аргументы, например:

```text
/c ""C:\RigolSorter\run_rigol_watch.cmd" "C:\RigolData\DHO814""
```

Для второго прибора — отдельная задача со своим аргументом каталога. Для задач без пользователя в системе убедитесь, что задана правильная учётная запись с разрешениями. Не запускайте одновременно два сортировщика **для одной и той же папки**; контроль `_logs/rigol_sort.lock` не допускает этого. После аварии не удаляйте lock, пока не убедитесь, что другой сортировщик уже не работает.

### Параметры командной строки

Из каталога программы, указав свою папку захвата:

```powershell
.\.venv\Scripts\python.exe rigol_sort.py --root "C:\RigolData\DHO814" --watch --min-age-seconds 60 --poll-seconds 5
.\.venv\Scripts\python.exe rigol_sort.py --root "C:\RigolData\DHO814" --dry-run
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

**Предупреждение:** команда `--dry-run` не удаляет исходные файлы, но может создавать служебные каталоги/журналы; для полноценной проверки сначала воспользуйтесь копией входящей папки. Счётчик можно восстановить через `--rescan-counter`. Не используйте `--force` с живыми файлами SMB.

## Настройка Quick на DHO814 и DHO924S

На осциллографе перейдите в **Utility → Quick** и выберите **Save Group**. В группе можно независимо включить:

| Пункт | Что сохраняется | Рекомендуемые настройки |
|---|---|---|
| **Save Image** | Изображение экрана (`PNG`) | Format `PNG`, Color `Color`, Invert `OFF` |
| **Save Wave** | Данные осциллограммы (`BIN` или `CSV`) | `Screen` / `Memory` по задаче; обычно `BIN` для компактного хранения, `CSV` для простого просмотра |
| **Save Setup** | Конфигурация прибора (`STP`) | Включить для повторяемых измерений |

После выбора трёх пунктов **одна аппаратная кнопка Quick сохраняет набор файлов**. Путь сохранения задаётся в **Storage → File Path**: выберите подключённый SMB-диск. Отключите перезапись `Overlay`, чтобы новые измерения не затирали старые. Если нужна только фотография/сигнал/настройки, можно оставить соответственно один или два пункта.

**PLA2216 / 16 цифровых каналов (DHO924S):** сигналы D0–D15 должны быть видимы на экране, если вы хотите видеть их в PNG. Наличие цифровых каналов на скриншоте не означает, что данные логического анализатора будут экспортированы как 16 отдельных колонок XLSX: это отдельная задача для поддержки конкретного формата экспорта.

Официальные руководства: [DHO800 User Guide](https://www.rigol.com/dam/global/downloads/brochures/en/user-manual/oscilloscopes/DHO800_UserGuide_EN.pdf), [DHO900 User Guide](https://www.rigol.com/dam/global/downloads/brochures/en/user-manual/oscilloscopes/DHO900_UserGuide_EN.pdf). См. разделы **Quick Action Settings**, **SMB Configuration**, **Store and Load**.

## Альтернатива: Samba на Debian (Linux)

Пример для отдельного пользователя `rigol` и папки `/srv/rigol/captures`. Настраивайте только в доверенной локальной сети, не открывайте TCP/445 в интернет.

```bash
sudo apt update && sudo apt install samba
sudo useradd -M -s /usr/sbin/nologin rigol
sudo mkdir -p /srv/rigol/captures
sudo chown -R rigol:rigol /srv/rigol
sudo chmod 0770 /srv/rigol/captures
sudo smbpasswd -a rigol
```

В конец `/etc/samba/smb.conf` добавьте:

```ini
[RigolData]
    path = /srv/rigol/captures
    browseable = yes
    read only = no
    guest ok = no
    valid users = rigol
    force user = rigol
    create mask = 0660
    directory mask = 0770
```

Проверьте конфигурацию и перезапустите сервис:

```bash
sudo testparm -s
sudo systemctl restart smbd
```

Для двух приборов разумно создать **раздельные каталоги/SMB-шары** (например, `DHO814` и `DHO924S`) и запустить **по одному наблюдателю на каждый**, иначе совпадающие имена `RigolDS1` от разных приборов могут случайно объединиться. В отдельные каталоги копируются файлы сортировщика. Не включайте SMB1 только ради совместимости, если подключение SMB2/SMB3 работает.

### Подключение Rigol к серверу

1. Подключите осциллограф к LAN и проверьте, что он видит IP-адрес Debian-сервера.
2. Откройте **Storage → SMB Setting**.
3. В **Server Path** введите `\\192.168.1.50\RigolData` (замените IP; имя SMB-шары должно быть латиницей).
4. **User Name:** `rigol`, **Password:** пароль из `smbpasswd`; нажмите **Connect** и проверьте `Connect State`.
5. По желанию включите **Boot Auto_Connect**; в Storage выберите сетевой диск как путь сохранения.
6. Сохраните тестовый набор по **Quick → Save Group**, проверьте появление PNG + BIN/CSV + STP на сервере и запуск сортировки.

Справка: раздел **SMB Configuration** официальных руководств Rigol содержит формат `\\IP\Share`, авторизацию, кнопку `Connect` и `Boot Auto_Connect`.

## Особенности и ограничения

- Обрабатываются только имена вида `RigolDS1.png`, `RigolDS1(2).bin` и т. п. в **корне** рабочей папки. Файлы с другими именами не перемещаются.
- Поддерживаемый BIN-парсер ожидает заголовок `RG03` и в текущей реализации рассчитан на **аналоговые каналы**; неизвестные двоичные форматы могут попасть в `_failed/` с объяснением. Не проверенные форматы цифрового захвата не заявляются как поддерживаемые.
- Для полных RAW-записей больше 3 млн отсчётов Excel формируется в формате preview/MinMax; исходный BIN/CSV остаётся в архиве.
- Исходные файлы **перемещаются**, поэтому экспериментировать лучше на копиях. Используйте `--dry-run` для оценки структуры, затем запускайте на тестовых данных.
- Это локальная утилита: никаких данных она не отправляет в интернет.
- В публичный GitHub не добавляйте реальные осциллограммы, сетевые пароли, IP и приборные настройки, которые считаете конфиденциальными. `.gitignore` исключает генерируемые данные.

## Проверка

```powershell
py -3 -m unittest discover -s tests -v
```

Присутствуют тесты ожидания полной минуты, группировки, сохранения STP/PNG и преобразования CSV в XLSX. Изменения не заменяют проверку на реальном SMB-сервере и каждом формате экспорта осциллографа.
